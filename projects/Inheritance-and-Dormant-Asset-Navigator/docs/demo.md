# Three reproducible demonstrations

Run `bash scripts/start.sh`, open the loopback URL, and use the prefilled demo password. Use `python -m scripts.demo` from the activated virtual environment for a fresh isolated automated rendition of all three scenarios; it does not alter an existing browser workspace.

## 1. Three institution paths

1. On Overview, inspect the three known assets and the separate ambiguous candidate. The two Harbor statements contribute only one asset and no recovery.
2. Choose Harbor's **Prepare packet**. Confirm the bank recipient and only three source records. Open a source using **Read**. The approval button remains disabled until the review checkbox is selected.
3. Approve the mock disclosure. The durable worker produces **Evidence requested**.
4. Prepare and approve Cedar's **inquiry**. It becomes **Human review** because Jordan Morgan is the named beneficiary. No insurance recovery appears.
5. Add the synthetic Summit claim form, then prepare and approve its packet. It resolves with a provider receipt for $86,740.25 simulated distribution.

## 2. Authority gap and follow-through

1. Open Harbor after its evidence request. Its checklist identifies the missing certified authority supplement.
2. Add the synthetic supplement. This returns only that asset to requirements-ready; the old disclosure is not silently expanded.
3. Prepare a new four-document packet, review the new hash and submission version, and explicitly approve.
4. Harbor resolves with $42,865.00 in verified simulated recovery. Aggregate verified recovery is $129,605.25 when Summit is also resolved. Cedar and the ambiguous candidate stay open; the estate is never labeled settled.
5. Open Activity to inspect the submitted, evidence-requested, new approval, institution-confirmed and resolved events.

## 3. Ambiguity and uncertain writes

1. Open **1 record needs a closer look**. Compare the similar name and equal masked ending with the distinct source owner ID and full synthetic reference. No submit action is available.
2. In a fresh workspace, choose **Simulator & operations**, select **Timeout after acceptance** for Harbor before drafting, then approve a packet.
3. The provider ledger records acceptance and the worker retains an unknown outcome. Advance the mock clock or wait for real-clock backoff. The same request is looked up and reconciled; only one provider write exists.
4. Repeat the failure-injection tests using the labeled evaluation command for delayed, declined, malformed, no-match and wrong-destination cases. A malformed response or unverified destination ends in operational review, never recovery.

All steps use fictional documents and mock institutions. The UI also supports inventory search/filter/export, source text upload/download, source hashes, draft revocation, bounded navigator guidance, and per-action replay visibility.
